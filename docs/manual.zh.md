# dsh bot 使用手册（大白话版）

> 这份手册假设你**完全不懂编程**。每一项设置都会用"这是干嘛的、你要不要管、填错会怎样"三句话说完。
> 想直接能用，跳到「第一次开机：8 步」（第 11 节）。

---

## 0. 这个东西到底是什么

你的电脑上装了一个很聪明的助手（DSH）。这个插件做的事只有一件：

> **让 QQ 变成那个助手的对讲机。**

你在 QQ 里给机器人发一句话，插件把它转给 DSH，DSH 想好了，插件再把答案送回 QQ。

所以它不是云服务、不联网存你的东西，**它就是在你这台电脑上跑的一个小管家**。

---

## 1. 装好之后在哪里找到它

打开 DSH 的网页界面（一般是 `http://127.0.0.1:3080`）→ 左下角**设置** → 侧栏里会多一项 **dsh bot**。

点进去，你会看到一排格子。别慌，**真正必须填的只有 4 个**，其余都是"默认就挺好"。

看不懂的那些（单个文件上限、同时处理的最大消息数、语音转写参数……）全被收进最下面的 **「高级设置（一般不用改）」** 折叠区里了，不点开就当它不存在。

---

## 2. 最上面那排按钮

| 你看到的 | 大白话 | 什么时候用 |
| --- | --- | --- |
| **启用**（勾选框） | "下次 DSH 一开机，就自动把机器人也拉起来" | 调通了以后再勾。第一次调别勾，手动点启动更好排查 |
| **启动** | 现在就把机器人叫醒 | 填完配置、点保存之后点它 |
| **停止** | 让机器人先睡一会儿，配置不会丢 | 想改配置、想省内存 |
| **重启** | 睡了再叫醒（等于先停再启动） | 改了配置不生效时点它 |
| **发送测试消息** | 让机器人**往你的 QQ 发一句「【测试】dsh bot 已连通…」**，用来一次确认"配置、连接、送达"三件事都通了 | 点完启动之后。没收到就说明还没通，先看下面第 12 节的排查表 |
| **完成** | 关掉这个设置页 | 随便点，不会丢东西 |
| **打开配置文件** | 直接把那个 JSON 文件用记事本打开 | 你好奇它到底存了什么 |

状态行那一串 `收到 0 / 已处理 0 / 拒绝 0 / 失败 0` 是计数器：来了几条消息、真正答了几条、被安全规则挡了几条、出错几条。**数字会动，说明它在干活。**

## 3. 必填的 4 个（不填跑不起来）

| 设置 | 大白话 | 你会填什么 |
| --- | --- | --- |
| **平台** | 你要用哪种方式连 QQ | 选 **QQ 官方机器人**（另一个 NapCat 是要在你电脑上挂一个真实 QQ 客户端，有封号风险） |
| **AppID** | 官方给你的机器人身份证号 | `102911163`（大龙虾那个） |
| **AppSecret** | 机器人的密码 | 去 QQ 开放平台后台复制。**它只存在你自己电脑上**，网页上永远显示成 `***` |
| **用户白名单** | 允许谁使唤这台电脑的"门禁名单" | 填你自己的 QQ 号，一行一个。**留空 = 拒绝启动**（故意的，见下面第 4 节） |

剩下那个 **DSH 入口路径** 也建议填上，不然它可能找不到 DSH 主程序：

```
E:\Local\npm\node_modules\@deepseek-ai\dsh\lib\bin.js
```

## 4. 安全设置：谁能用、用多快

| 设置 | 大白话 | 默认 | 填错的后果 |
| --- | --- | --- | --- |
| **用户白名单** | "门禁名单"，只有名单上的 QQ 号能用 | 空 | **空着不让启动**。因为底层语义是"空着等于谁来都行"，那等于把电脑交给陌生人 |
| **群白名单** | 只有名单上的群能用（机器人被拉进别的群也不理） | 空 = 不按群管 | 填了群号却把人漏了 → 群里@它没反应 |
| **允许私聊** | 私聊它管不管 | 开 | 关掉后私聊完全没反应 |
| **允许群聊** | 群里管不管 | 开 | 关掉后群里@它也没反应 |
| **群聊必须 @ 机器人** | 群里必须"@它"才理，不然当没听见 | 开 | 关掉后群里任何一句话它都可能插手（很吵，也费钱） |
| **每人每分钟消息上限** | 一个人一分钟最多问几次，防止刷屏 | 6 | 填 10 以上遇到手滑连发会被限流；填 0 = 不限流（不推荐） |
| **同时处理的最大消息数** | 同时最多几个问题一起想 | 2 | 每多一个就多占约 300MB 内存；调太大电脑会卡 |
| **单条 prompt 字符上限** | 一次最多把它能看的文字截到多长 | 8000 | 太小会截断长文档；太大会很慢很贵 |

**为什么会"拒绝启动"？** 因为底层代码里"名单空着"等于"不按人管"——所有人都能驱动你电脑上的 DSH。插件层故意把这种情况拦下来，宁可不让开机，也不让陌生人随便用你的电脑。

## 5. 文件存在哪、留多久

| 设置 | 大白话 | 默认 | 备注 |
| --- | --- | --- | --- |
| **数据目录** | 机器人的"仓库"：别人发的图片、文档、语音都存这儿 | `E:\dsh-im-bridge-data` | **绝对路径**，别放 C 盘（C 盘满了电脑会出毛病）。放 C 盘会给你黄字警告 |
| **单个文件上限（字节）** | 太大的文件不收 | 104857600（=100MB） | 超了会把半截文件删掉并回你一句"太大" |
| **附件保留天数** | 仓库里的东西留几天，过期自动清 | 30 | 只清附件，不动日志、不动你的工作目录 |

## 6. 回复长什么样

| 设置 | 大白话 | 默认 |
| --- | --- | --- |
| **单条回复最大字符数** | 一条消息最多多长，超了就拆成几条发 | 1500 |
| **单条回复最多多少字（0=不限）** | 再长就直接截断，末尾告诉你"太长截断了，总共 N 字"，然后才分段 | 0（不限） |
| **发送前停顿（毫秒/每字）** | 假装在打字：每字等这么久再发。0=立刻发 | 0 |
| **停顿最多等多久（毫秒）** | 上面那个停顿的封顶，外加 ±20% 随机浮动，免得每次都一样长 | 3000 |
| **错误回复前缀** | 出错时的提示前面加个标签，方便认 | `[bridge] ` |
| **回复里附带会话 id** | 每条回复后面带上内部编号（排查问题用） | 关 |

> 停顿只用在**最终回复**上：收到消息的「开始处理」回执、处理中的进度提示照旧秒回。

> ⚠️ 官方 QQ 机器人有个硬规矩：**一条消息最多回 4 次（私聊，60 分钟内）/ 5 次（群聊，5 分钟内）**。所以长答案被拆太多条时，后面的会被平台拒掉。这项还在优化，建议先把"单条回复最大字符数"设大一点（比如 3000），少拆几条。

## 7. 语音消息（可以不管）

QQ 语音是特殊格式，**DSH 听不见**。这里留了个"翻译官"的位置：

| 设置 | 大白话 | 默认 |
| --- | --- | --- |
| **语音转写命令** | 你想用的语音转文字程序（比如 whisper） | 空 = 不转写，只把文件存下来并告诉 DSH 路径 |
| **语音转写参数** | 传给那个程序的参数，一行一个 | 空 |
| **语音转写超时（毫秒）** | 转写最多等多久 | 60000 |

没填也能用，只是 DSH 会"看到"一个语音文件而不是听懂它说的话。

## 8. 日志（出问题时看这里）

| 设置 | 大白话 | 默认 |
| --- | --- | --- |
| **日志级别** | 记多细：`debug` 全记、`info` 正常、`warn` 只记问题、`error` 只记错误 | `info` |

日志文件在 **`<数据目录>\logs\bridge-YYYY-MM-DD.log`**。机器人不回你话的时候，第一个该看的就是它。

## 9. DSH 相关（一般不用动）

| 设置 | 大白话 | 默认 |
| --- | --- | --- |
| **DSH 入口路径** | DSH 主程序在哪 | 空 = 自动找（本机建议手填，见第 3 节） |
| **DSH profile 名** | 用哪一套 DSH 设置 | `im-bridge` |
| **DSH 工作目录** | DSH 干活时的文件夹，它只能改这里面的东西 | 空 = `<数据目录>\workspace` |
| **单次 DSH 调用超时（毫秒）** | 一个问题最多等多久，超了就放弃 | 300000（5 分钟） |

> **它会不会乱删我文件？** 不会。机器人跑 DSH 时用的是"只能改自己文件夹"的模式（`workspace-write`），碰不到系统盘和别的目录。写 `danger-full-access` 会被当配置错误直接拒绝——这是故意的。

## 10. 平台专属的两组

**QQ 官方机器人**（推荐）

| 设置 | 大白话 | 备注 |
| --- | --- | --- |
| **AppID** | 机器人身份证 | 后台可见 |
| **AppSecret** | 机器人密码 | 后台可见，只存本机 |

| 设置 | 大白话 | 默认 |
| --- | --- | --- |
| **WebSocket 地址** | NapCat 在本机开的门牌号 | `ws://127.0.0.1:3001` |

| **重连最小/最大间隔（毫秒）** | 掉线后多久重试、最长等多久 | 1000 / 30000 |

## 11. 第一次开机：先点通三步向导

设置页最上面多了一张 **「连接向导（三步点通）」** 卡片。装完先照着它点，比在下面几十个字段里翻快得多——每步都会告诉你"现在是什么状态、下一步该改哪"。

**第 1 步 · 去开放平台**

点卡片里的 **「打开开放平台」**（旁边有「复制链接」，粘进浏览器也行）：`https://q.qq.com/qqbot/#/developer`
用手机 QQ 扫码登录 → 创建机器人 → 进 **「开发设置」**，`AppID` 和 `AppSecret` 就在那一页。

> 二维码以后会直接画在卡片里，这一步先只给链接。

**第 2 步 · 填凭证并验证**

把 AppID / AppSecret 填进卡片里的两个框，点 **「验证凭证」**。它只做两件事：拿 token、再拉一次网关地址——**不改配置、也不启动机器人**，所以随便点。

| 你看到的 | 意思 | 怎么办 |
| --- | --- | --- |
| `✅ 已连通：…（沙箱环境）` | token 和网关都通了 | 往下走第 3 步 |
| `AppSecret 不对：去开放平台 → 开发设置 → 重置密钥` | 密钥抄错、或后台重置过 | 重新复制一次密钥填进来 |
| `机器人还没发布：把「沙箱环境」打开，并把自己的号加进体验成员` | 机器人还没上线，只能在沙箱跑 | 开放平台里开沙箱、把自己加进体验成员 |
| `连不上 QQ 开放平台：…` | 网络 / 代理的问题，**跟密钥无关** | 先确认这台电脑能上网，再点一次 |

> **NapCat 平台不用开放平台**：第 1 步的按钮会变成 `http://127.0.0.1:6099`，用手机 QQ 扫码登录 NapCat 后台；第 2 步没有凭证要填，直接跳到第 3 步。

**第 3 步 · 发条测试消息**

先按下面第 6、7 步 **保存 + 启动**（状态行显示「运行中」），再点卡片里的 **「发条测试消息」**：QQ 收到「【测试】dsh bot 已连通…」就说明**配置、连接、送达**三件事全通了。

**补齐剩下几项**

4. **用户白名单**（页面上叫「谁能用」）填你自己的 QQ 号（比如 `1772538871`）。
5. **DSH 入口路径** 填 `E:\Local\npm\node_modules\@deepseek-ai\dsh\lib\bin.js`。
6. 点 **保存**（这时"启用"别勾）。状态行会显示「已停止 · 启用关 · 平台 qq-official」。
7. 点 **启动**。状态行变成「运行中」。
8. 点 **「发送测试消息」**，然后看你的 QQ：收到「【测试】dsh bot 已连通，这是一条来自你电脑的消息。」就说明通了——配置、连接、送达三件事全对。
   - 页面显示「已发送给 ……」但 QQ 没收到：号填错了 / 机器人没把你加进「开发体验用户」/ 平台权限没开（看第 12 节）；
   - 页面直接说「没发出去：机器人还没启动」：第 7 步没成功，回第 6、7 步；
   - 页面说「不知道该把测试消息发给谁」：第 4 步的号没填，或者在「测试消息发给谁」里手填一个。

> 测试通过以后，用你自己的 QQ 给机器人发一句「你好」，正式聊一次。

> 机器人**不能主动找你聊天**（平台限制），必须你先发第一条，它才能回。

## 12. 它不听话时，按这个顺序查

| 现象 | 最可能的原因 | 怎么办 |
| --- | --- | --- |
| 点启动被拒，说"白名单为空" | 第 4 节说的安全拦截 | 用户白名单填上你自己的号 |
| 状态行「运行中」但发消息没反应 | 白名单里没有你 / 群里没 @ 它 / 平台权限没开 | 核对白名单；群里记得 @；看日志里的错误码 |
| 日志出现 `4013` / `4014` | 机器人没拿到"收发消息"权限 | 去开放平台申请事件权限（intents `33554432`） |
| 日志出现 `4914` | 连错了环境（沙箱 / 正式） | 目前只支持正式环境，确认机器人已上线 |
| 日志出现 `spawn_error` / `cwd_missing` | 找不到 DSH 或工作目录建不出来 | 检查第 9 节的入口路径与工作目录 |
| 回了半句就没了 | 官方平台"最多回 4/5 次"的限制 | 把"单条回复最大字符数"调大（如 3000），让它少拆几条 |
| 点「发送测试消息」提示"机器人还没启动" | 运行时没起来，发不出去 | 先点 **启动**，状态行显示「运行中」再点测试 |
| 点「发送测试消息」提示"不知道该把测试消息发给谁" | 白名单里没有一个能当收件人的号 | 在「谁能用」里填你自己的号，或在「测试消息发给谁」里手填 |
| 提示"已发送给 xxx"但 QQ 没收到 | 号填错 / 没把自己加进机器人的「开发体验用户」 / 机器人没拿到收发消息权限 | 核对号；去开放平台加开发体验用户、申请事件权限 |
| 设置页整个不见了 | 插件没装好或 DSH 没重启 | 重启 `dsh web`；仍不行看 `profiles/web/package.json` 的 `bundles` 里有没有 `dsh-im-bridge` |

## 14. 一句话记住的默认值

- 数据在 **E:\dsh-im-bridge-data**，别放 C 盘。
- 名单空着 **不让开机**（安全）。
- 一个人一分钟最多 **6** 条，同时最多 **2** 个问题在跑。
- 一次最多看 **8000** 字，一条回复最多 **1500** 字。
- 附件留 **30** 天，超大文件（>100MB）不收。
- DSH 只能改它自己的文件夹，碰不到系统。

## 15. 三个容易踩的细节（2026-10 更新）

### 会话落在哪个工作区

机器人**自己建会话**时会：

1. 用配置里的「数据目录 + workspace」（默认 `<数据目录>\workspace`，你可以在设置页把 `dsh.cwd` 指到任意目录，例如 `E:\dsh\dsh-bot-msg`）；
2. 建完后**自动把这个会话登记进同名工作区**（GUI 左侧那个分组）。
   所以你在 GUI 里能看到它、点开能看历史、能接着聊——不需要手动拖。

> 注意：工作区归属是**显式成员表**。**已经存在的旧会话不会自动搬家**，只有重启后新建的会话会进组。

### 审批怎么回

弹出来的审批卡片，回这些任意一个都行：

| 意图 | 可以回 |
| --- | --- |
| 放行（仅这一次） | `1`、`确认`、`允许`、`同意`、`好的`、`可以` |
| 拒绝 | `2`、`拒绝`、`不行`、`不要` |
| 取消 | `0`、`取消` |

超过 `approval.timeoutMs`（默认 5 分钟）没回，按**拒绝**处理——这是故意的：`取消` 会让模型立刻重试同一个操作，形成死循环。

### 为什么有些写入不弹审批、有些弹

沙箱的"根"是**DSH 主进程启动时所在的目录**（不是会话的 cwd）。所以：

- 从 `E:\dsh\dsh-bot-msg` 目录启动 `dsh web` → 它写这个目录**不弹**；
- 让它写别处（例如 `E:\dsh-im-bridge-data\`）→ 弹一次，回 `确认` 放行。

## 16. 在 QQ 里发命令（2026-10 新增）

有些事**不用麻烦 DSH**，直接发一条命令就行——回得快，也不占"同时几个问题在跑"的名额：

| 你发 | 也可以发 | 会发生什么 |
| --- | --- | --- |
| `/new` | `/新会话` | 开一个新会话。**下一条**消息才用新会话（正在跑的那一轮先跑完） |
| `/status` | `/状态` | 回你四件事：平台、跑法（inprocess/sdk/headless）、会话编号前 8 位、上一轮花了多久；有审批或提问挂着时多一行 |
| `/export` | `/导出` | 把当前会话导成 markdown 文件，回你**绝对路径**和消息条数 |
| `/help` | `/帮助` | 把上面这张表回给你 |

几条规矩：

- 命令要**以 `/` 开头**。`我在 /new 你说呢` 这种不算命令，会照常发给 DSH；
- 命令**不进 DSH**：不消耗模型、不产生会话、不影响上下文；
- `/export` 导出的文件在 `<数据目录>/history` 里（默认 `E:\dsh-im-bridge-data\history`），
  只导你和 DSH 说的话，工具调用和思考过程不进文件；
- 导出用的是 DSH 自己写的历史日志，所以得等那一轮落盘（跑完一般就已经落了）。

## 17. "网页里点开是空白 / QQ 说会话被占用"是怎么回事（2026-10 修复）

DSH 的一条会话同一时刻只有一个"写句柄"。以前会出现两种怪状：

1. 网页里点开机器人建的那条会话 → **历史空白**；
2. 你在网页开着它的时候，QQ 发消息 → 报 `session "…" is already owned by an active write handle`，整轮失败。

现在这么处理：

- **锁**：同一个聊天窗口（同一个 QQ 号/群）的消息排队进出，两条并发消息不会各自读到一个"空绑定"，也就不会建出两个会话；
- **退避重试**：抢写句柄先等 200ms、600ms、1200ms 重试，网页只是短暂占用时你根本感觉不到；
- **兜底**：三次都抢不到才换一条新会话继续回你（上下文断一次，但答案不丢），这件事只写日志，不会在 QQ 里打扰你；
- `dsh.releaseOnIdle` 保持默认关；`dsh.newSessionPerMessage` 现在是**调试开关**，正常别开。


## 附：让它发图 / 发语音

回复正文里单独写一行标记，它就会真的把东西发出来（不是只回一行路径）：

| 你想要的 | 它在正文里写的 |
| --- | --- |
| 文件 | `[[sendfile: C:\data\报告.docx]]` |
| 图片 | `[[sendimage: C:\data\图.png]]` |
| 语音 | `[[sendvoice: C:\data\说一句.amr]]` |

- 每种最多 3 个；路径必须是真实存在的绝对路径，写错的会被跳过，并在文字里告诉你跳过了几个、为什么；
- **QQ 官方机器人不支持语音消息**：`sendvoice` 会自动改成"当文件发 + 一句说明"，日志里留一条 warn（NapCat 那条路能真发语音）；
- 你不需要记这些标记，直接说「把图发我 / 发段语音」就行，模型知道该写哪个。

## 附：群里怎么触发它

默认情况下群里必须 **@ 它** 才理。想让它更"在场"一点，有两个开关（都在「高级设置」里）：

| 设置 | 大白话 | 默认 |
| --- | --- | --- |
| **这些词出现就一定回（一行一个，群聊免 @）** | 写上「发布」「上线」「报错」这类词：群里出现就一定回，**优先于"必须 @"** | 空 |
| **没 @ 也接话的概率（0~1）** | 没 @ 也没命中必答词时，按这个概率插一句。0=不插 | 0 |

这两个都是**被动**的：一定是群里先有人说话，它才判断这一次要不要接。它不会自己定时开口——那是另一套东西（需要节流、静默时段、避免连着刷屏），今天没做。

命中必答词时日志里会有一行 `群里出现必答词「发布」，没 @ 也回：userId=… groupId=…`；按概率接话记在 debug 级别，排查"它为什么插嘴"时把日志级别调成 debug 就能看到。

## 附：把文件发回 QQ

> 想让它把文件发回 QQ，直接说「把结果发我」——它会真的把文件传过来（一条回复最多 3 个），而不是只回一行路径；文件太大（超过第 5 节的单个文件上限）或路径写错的会跳过，并在文字里告诉你跳过了几个、为什么。
